PAKET EMAIL NOTIFIKASI (lewat antrean/queue)

Email yang dikirim:
  Pembeli : pesanan dibuat | pembayaran diterima | pesanan dikirim (dengan nomor resi)
  Admin   : pesanan baru   | pembayaran diterima (perlu diproses)

Semua email masuk antrean, jadi checkout tidak melambat. Kegagalan email TIDAK pernah
menggagalkan pesanan atau pembayaran (kegagalan dicatat, dan bisa dicoba ulang).

A. PASANG PAKET
   1. Pastikan pesanan admin sebelumnya sudah di-commit (git status = "working tree clean").
   2. Ekstrak zip ke folder projek (C:\laragon\www\Website-Penjualan-Toko).
      Windows akan bertanya "Replace or Skip" untuk 2 file ini. Pilih REPLACE:
          app\Providers\EventServiceProvider.php
          app\Http\Controllers\Shop\CheckoutController.php
      EventServiceProvider hanya DITAMBAH daftar listener (isi bawaan Laravel tetap ada).
      CheckoutController hanya DITAMBAH satu baris event setelah pesanan dibuat.
      File lain semuanya baru. Tidak ada migration (tabel jobs dan failed_jobs sudah ada).

B. ATUR .env  (jangan di-commit; App Password rahasia)
       APP_URL=http://website-penjualan-toko.test
       QUEUE_CONNECTION=database

       MAIL_MAILER=smtp
       MAIL_HOST=smtp.gmail.com
       MAIL_PORT=587
       MAIL_USERNAME=emailtoko@gmail.com
       MAIL_PASSWORD=app-password-16-huruf-tanpa-spasi
       MAIL_ENCRYPTION=tls
       MAIL_FROM_ADDRESS=emailtoko@gmail.com
       MAIL_FROM_NAME="Nama Tokomu"

       SHOP_NAME="Nama Tokomu"
       SHOP_ADMIN_EMAIL=emailkamu@gmail.com

   - APP_URL penting: tombol di dalam email memakai alamat ini.
   - SHOP_ADMIN_EMAIL: tujuan semua email untuk admin. Akun seeder admin@toko.test adalah alamat
     fiktif, jadi isi dengan emailmu yang nyata supaya email admin benar-benar sampai.
   - Gmail membutuhkan App Password (Akun Google -> Keamanan -> Verifikasi 2 Langkah aktif ->
     Sandi aplikasi). Password Gmail biasa ditolak.
   - Mau mencoba tanpa Gmail dulu? Pakai MAIL_MAILER=log. Email akan ditulis ke
     storage\logs\laravel.log (bukan dikirim sungguhan).

   Lalu:
       php artisan config:clear
       php artisan optimize:clear

C. UJI PENGATURAN EMAIL
       php artisan shop:test-mail emailkamu@gmail.com
   Harus muncul "Email uji dikirim" dan email tiba (cek juga folder Spam). Kalau muncul
   "Gagal mengirim", pesan errornya menunjukkan apa yang salah (misalnya
   "Username and Password not accepted" = App Password salah atau Verifikasi 2 Langkah belum aktif).

D. JALANKAN PEKERJA ANTREAN
   Karena QUEUE_CONNECTION=database, email diproses oleh "worker". Di terminal terpisah,
   biarkan terbuka selama pengujian:
       php artisan queue:work
   Setelah mengubah .env atau kode, hentikan worker (Ctrl+C) lalu jalankan lagi.
   (Mau coba tanpa worker? Set QUEUE_CONNECTION=sync; email dikirim langsung saat itu juga,
   tetapi checkout menunggu pengiriman email selesai.)

E. TES ALUR LENGKAP
   Email pembeli tujuan harus alamat NYATA. Daftar akun baru di /register dengan emailmu,
   atau pakai trik Gmail: emailkamu+pembeli1@gmail.com tetap masuk ke kotak masukmu.
   (Akun seeder pembeli@toko.test adalah alamat fiktif.)

   1. Checkout satu pesanan sebagai pembeli.
      -> Pembeli: "Pesanan ... berhasil dibuat".  Admin (SHOP_ADMIN_EMAIL): "Pesanan baru ...".
   2. Bayar pesanan (popup Midtrans, atau: php artisan payments:simulate INV-... settlement).
      -> Pembeli: "Pembayaran pesanan ... diterima".  Admin: "Pembayaran diterima: ...".
   3. Sebagai admin: Proses pesanan, lalu Kirim pesanan dengan nomor resi.
      -> Pembeli: "Pesananmu ... sedang dikirim" berisi kurir dan nomor resi.
   4. Klik tombol di dalam email -> terbuka halaman pesanan yang benar.
   5. Ulangi payments:simulate ... settlement untuk pesanan yang sama -> email "dibayar" TIDAK
      terkirim dua kali.
   6. Matikan worker (Ctrl+C), buat pesanan -> checkout tetap cepat dan sukses. Cek tabel "jobs"
      di HeidiSQL: ada baris menunggu. Nyalakan worker lagi -> email terkirim, baris hilang.
   7. Sengaja salahkan MAIL_PASSWORD, jalankan config:clear dan restart worker, buat pesanan:
      checkout TETAP sukses. Setelah 3 kali percobaan, pekerjaan masuk tabel "failed_jobs".
      Lihat dengan: php artisan queue:failed
      Perbaiki .env, restart worker, lalu ulangi pengiriman: php artisan queue:retry all

F. PEMECAHAN MASALAH
   - Email tidak datang tetapi tidak ada error: worker belum jalan, atau tabel "jobs" menumpuk.
     Jalankan php artisan queue:work, dan cek folder Spam.
   - Tombol email menuju alamat salah: perbaiki APP_URL lalu restart worker.
   - Setelah mengubah .env, selalu php artisan config:clear dan restart worker.

G. COMMIT DAN PUSH
       git add .
       git commit -m "Email notifikasi pesanan lewat antrean"
       git push
   Pastikan git status TIDAK menampilkan file .env.
