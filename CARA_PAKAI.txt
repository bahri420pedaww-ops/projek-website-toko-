PAKET PAYMENT GATEWAY MIDTRANS (Snap, sandbox)

Tidak ada paket Composer baru yang perlu dipasang (memakai HTTP client bawaan Laravel).
Tidak ada migration baru (tabel payments sudah ada sejak paket database).

A. SIAPKAN AKUN MIDTRANS SANDBOX
   1. Daftar di https://dashboard.sandbox.midtrans.com (gratis), buat merchant uji.
   2. Pastikan lingkungan di dashboard = SANDBOX.
   3. Buka Settings -> Access Keys. Salin Server Key (SB-Mid-server-...) dan
      Client Key (SB-Mid-client-...). Server Key rahasia: jangan dikirim ke siapa pun,
      jangan di-commit.

B. PASANG PAKET
   1. Pastikan ongkir sebelumnya sudah di-commit (git status = "working tree clean").
   2. Ekstrak zip ke folder projek (C:\laragon\www\Website-Penjualan-Toko).
      Windows akan bertanya "Replace or Skip" untuk 2 file ini. Pilih REPLACE:
          app\Http\Controllers\Shop\OrderController.php
          resources\views\shop\orders\show.blade.php
      Keduanya buatan paket sebelumnya (hanya DITAMBAH: pengecekan status dan blok
      pembayaran). Kalau teman sudah mengubah view detail pesanan, JANGAN timpa; kabari saya.
      File lain semuanya baru.
   3. Buka routes/web.php, tambahkan SATU baris ini di dekat require account.php:
          require __DIR__.'/payment.php';
   4. Buka file .env, tambahkan (isi dengan kunci milikmu):
          MIDTRANS_SERVER_KEY=SB-Mid-server-xxxxxxxxxxxx
          MIDTRANS_CLIENT_KEY=SB-Mid-client-xxxxxxxxxxxx
          MIDTRANS_IS_PRODUCTION=false
          MIDTRANS_EXPIRY_HOURS=24
          MIDTRANS_VERIFY_SSL=true
   5. Terminal Laragon (folder projek):
          php artisan optimize:clear
          php artisan route:list --name=payments
      Harus muncul payments.show, payments.check, payments.notification.

C. TES (npm run dev berjalan; komputer ONLINE)
   1. Login pembeli, buat satu pesanan lewat checkout. Di detail pesanan (status
      "Menunggu pembayaran") klik "Bayar sekarang".
   2. Halaman pembayaran terbuka dan popup Midtrans muncul. Pilih satu metode lalu bayar di
      simulator sandbox:
        - Kartu kredit: nomor uji 4811 1111 1111 1114, CVV 123, tanggal kedaluwarsa bebas
          (masa depan), OTP 112. Kalau ditolak, lihat daftar kartu uji di dokumentasi Midtrans.
        - Transfer bank / QRIS / e-wallet: Midtrans menyediakan simulator pembayaran sandbox
          di https://simulator.sandbox.midtrans.com (tempel nomor VA atau kode QR dari popup).
   3. Setelah popup menyatakan sukses, kamu dikembalikan ke detail pesanan dengan status
      "Sudah dibayar" dan pesan hijau. (Ini berjalan tanpa webhook, lewat pengecekan status.)
   4. Cek HeidiSQL:
        - payments: 1 baris, status settlement, transaction_id, payment_type, paid_at terisi
        - orders: status paid
        - order_status_histories: ada baris paid
   5. Buka /pesanan/{kode}/bayar berkali-kali untuk pesanan yang masih pending -> tabel
      payments tetap 1 baris (token dipakai ulang, tidak membuat transaksi ganda).
   6. Tutup popup tanpa membayar -> pesanan tetap pending. Klik "Cek status pembayaran" ->
      muncul pesan "Pembayaran belum diterima".
   7. UJI WEBHOOK TANPA INTERNET (simulasi notifikasi dengan signature benar):
          php artisan payments:simulate INV-XXXXXXXX-XXXXXX settlement
      -> pesanan paid. Ulangi perintah yang sama -> tidak ada perubahan ganda.
      Lalu:  php artisan payments:simulate INV-XXXXXXXX-XXXXXX pending
      -> pesanan TETAP paid (notifikasi terlambat tidak menurunkan status).
      (Ganti INV-... dengan gateway_order_id di tabel payments. Buka halaman bayar sebuah
      pesanan dulu agar barisnya ada.)
   8. UJI KEDALUWARSA: buat pesanan baru, buka halaman bayar-nya, lalu:
          php artisan payments:simulate INV-YYYYYYYY-YYYYYY expire
      -> pesanan cancelled, stok produk KEMBALI bertambah, riwayat status tercatat.
   9. UJI PEMBATALAN OTOMATIS: ubah kolom created_at sebuah pesanan pending (tanpa
      pembayaran) di HeidiSQL menjadi 2 hari lalu, lalu:
          php artisan orders:expire-unpaid
      -> pesanan cancelled dan stok kembali. Pesanan yang baru dibuat tidak tersentuh.
  10. UJI KEAMANAN: kirim notifikasi dengan signature palsu. Di Git Bash:
          curl -i -X POST http://website-penjualan-toko.test/midtrans/notification \
            -H "Content-Type: application/json" \
            -d '{"order_id":"x","status_code":"200","gross_amount":"1.00","signature_key":"palsu"}'
      -> harus 403. Notifikasi tanpa signature yang benar tidak pernah mengubah apa pun.
  11. Login sebagai pembeli lain, buka /pesanan/{kode pesanan orang lain}/bayar -> 404.

D. WEBHOOK ASLI (OPSIONAL)
   Server Midtrans tidak bisa menjangkau "website-penjualan-toko.test" karena alamat itu hanya
   ada di komputermu. Untuk menerima notifikasi asli, buka terowongan (tunnel) gratis seperti
   ngrok atau Cloudflare Tunnel ke situs lokalmu, lalu di dashboard sandbox:
       Settings -> Configuration -> Payment Notification URL
       isi:  https://ALAMAT-TUNNEL-KAMU/midtrans/notification
   Tanpa tunnel pun semuanya tetap bisa didemokan lewat popup (otomatis cek status) dan
   tombol "Cek status pembayaran".

E. PEMBATALAN OTOMATIS TERJADWAL (OPSIONAL)
   Untuk menjalankan orders:expire-unpaid otomatis, tambahkan di method schedule()
   pada app/Console/Kernel.php:
          $schedule->command('orders:expire-unpaid')->hourly();
   lalu biarkan terminal berikut berjalan saat demo:
          php artisan schedule:work

F. PEMECAHAN MASALAH
   - "MIDTRANS_SERVER_KEY belum diatur": isi .env lalu jalankan php artisan config:clear.
   - "Server Key Midtrans tidak valid (401)": kunci salah salin, atau memakai kunci
     production padahal MIDTRANS_IS_PRODUCTION=false (harus sama-sama sandbox).
   - "cURL error 60" / sertifikat SSL: PHP di Windows belum punya daftar sertifikat (CA).
     Solusi benar: unduh https://curl.se/ca/cacert.pem, simpan misalnya di
     C:\laragon\etc\ssl\cacert.pem, lalu di php.ini (Laragon: Menu -> PHP -> php.ini)
     isi curl.cainfo="C:\laragon\etc\ssl\cacert.pem" dan openssl.cafile dengan alamat yang
     sama, lalu restart Apache. Hanya untuk debugging lokal sementara, boleh set
     MIDTRANS_VERIFY_SSL=false di .env (jangan dipakai selain di komputermu).
   - Popup tidak muncul: pastikan MIDTRANS_CLIENT_KEY terisi dan komputer online
     (Snap.js diunduh dari server Midtrans). Buka Console browser (F12) untuk melihat pesan.
   - "Gross amount tidak sama dengan jumlah item" dari Midtrans: kabari saya beserta
     pesan lengkapnya.
