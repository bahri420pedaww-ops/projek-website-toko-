PAKET PESANAN UNTUK ADMIN (daftar, detail, ubah status, resi, pembatalan)

Alur status:  pending -> paid -> processing -> shipped -> completed
              pending -> cancelled (stok dikembalikan; pesanan yang sudah dibayar tidak bisa dibatalkan)

Prasyarat: paket checkout, ongkir, dan midtrans sudah terpasang dan lolos tes.

1. Pastikan pekerjaan sebelumnya sudah di-commit (git status = "working tree clean").

2. Ekstrak zip ke folder projek (C:\laragon\www\Website-Penjualan-Toko).
   Windows akan bertanya "Replace or Skip". Pilih REPLACE untuk semua yang ditanyakan:
       app\Services\MidtransClient.php
       app\Services\OrderService.php
       app\Http\Controllers\Admin\CustomerController.php
       routes\admin.php
       routes\shop.php
       resources\views\admin\dashboard.blade.php
       resources\views\admin\customers\show.blade.php
       resources\views\shop\orders\show.blade.php
   Semuanya buatan paket sebelumnya; isinya hanya DITAMBAH (tidak ada yang hilang).
   MidtransClient tetap menyertakan fitur ngrok, jadi aman walau paket ngrok belum dipasang.
   Kalau teman sudah mengubah view pembeli (orders\show), JANGAN timpa view itu; kabari saya.
   File baru: OrderManagementService, OrderShipped, DashboardController, OrderController
   (admin), OrderActionController (pembeli), dan view admin\orders.
   Tidak ada migration baru. Tidak perlu mengedit routes/web.php.

3. Terminal Laragon (folder projek):
       php artisan optimize:clear
       php artisan route:list --name=orders
   Harus muncul admin.orders.index, admin.orders.show, admin.orders.process, admin.orders.ship,
   admin.orders.complete, admin.orders.cancel, orders.cancel, orders.receive, dan route lama.

4. Tes. Siapkan beberapa pesanan lewat akun pembeli. Untuk membuat pesanan "sudah dibayar"
   tanpa menunggu simulator, gunakan:
       php artisan payments:simulate INV-XXXXXXXX-XXXXXX settlement
   (buka halaman bayar pesanannya dulu agar baris pembayaran ada).

   a. /admin -> ada kartu hitungan (perlu diproses, perlu dikirim, sedang dikirim, menunggu
      pembayaran) dan tautan "Kelola Pesanan".
   b. /admin/orders -> daftar pesanan. Tab status menampilkan jumlah per status, kolom pencarian
      bekerja (kode, nama penerima, nama atau email pembeli).
   c. Pesanan "Menunggu pembayaran" -> detail -> "Batalkan pesanan":
        - status cancelled, stok produk KEMBALI, riwayat tercatat "Dibatalkan oleh admin."
        - baris payments yang pending menjadi cancel
        - (opsional) di dashboard Midtrans sandbox, transaksi itu ikut dibatalkan
   d. Pesanan "Sudah dibayar" -> "Proses pesanan" -> status "Diproses".
   e. Pesanan "Diproses": klik "Kirim pesanan" dengan resi KOSONG -> ditolak (pesan wajib diisi).
      Isi resi lalu kirim -> status "Dikirim"; baris shipments terisi (tracking_number, shipped_at).
   f. Login sebagai pembeli, buka pesanan itu -> tampil status Dikirim dan nomor resi, serta
      tombol "Pesanan sudah diterima". Klik -> status "Selesai"; shipments.delivered_at terisi.
   g. Buka dua tab untuk pesanan "Sudah dibayar", klik "Proses pesanan" di tab pertama lalu di
      tab kedua -> tab kedua menampilkan pesan error, riwayat tidak dobel.
   h. Pembeli dengan pesanan "Menunggu pembayaran" -> klik "Batalkan pesanan" -> dibatalkan,
      stok kembali. Pesanan yang sudah dibayar tidak punya tombol batal.
   i. Login sebagai pembeli, buka /admin/orders -> harus 403.
   j. Akun pembeli lain membuka /pesanan/{kode pesanan orang lain} -> 404.
   k. /admin/customers/{id pembeli} -> ada daftar pesanan terakhir dan total belanja
      (hanya pesanan yang sudah dibayar sampai selesai).

5. Commit dan push:
       git add .
       git commit -m "Pesanan untuk admin: daftar, status, resi, pembatalan"
       git push

6. Kirim docs/KONTRAK_PESANAN.md ke teman (frontend).
